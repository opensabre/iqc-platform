# 基于校准证据的成本级联

PRD8.3要求低成本引擎优先、置信度不足升级，P2要求成本优化路由。已有PipelineRuntime条件、依赖、Fallback、原校准证明与网关计量，不新建路由服务/表/API。普通LESS_THAN在null上返回false，不能表达缺测也升级；因此在原条件协议扩展一个明确操作，不改变旧比较语义。

```json
{"pointer":"/upstream/cheap","operator":"CALIBRATED_CONFIDENCE_BELOW","value":0.8}
```

把此条件放在昂贵LLM节点，并在dependsOn加入cheap。cheap先通过已冻结的来源/部署绑定校准后发布结果到upstream。条件检查完整节点结果：SUCCESS、唯一KNOWN的LLM/SMALL_MODEL事实、0–1有限置信度，以及原六字段证明的schema/ArtifactHash格式/事实ID/supported/原始值范围/转换值一致。达到阈值（含等号）跳过升级，否则执行。0是合法置信度；阈值0也须真实支持，不能以未知当0。未校准的高自报值、未知状态、无分箱支持、多事实和缺/坏证明都不能阻止升级。

这里只消费原可信运行输出的结构证据，不从客户端JSON认定系数有效；原CalibrationRuntime在上游应用和运行后/保存重读边界继续按任务原Artifact重算。单凭proof标签/Hash格式不能替代原来源和系数验证，不能将任意输入或变量指针接到本操作。指针限定一个upstream节点并显式声明依赖。节点ERROR/TIMEOUT不满足原依赖成功前提，按原Fallback解决，不借置信度条件绕过错误策略。

策略作者仍需决定节点顺序、阈值、事实代码、Fusion优先级与Fallback。校准拟合源与目标检测图相同，未校准拟合执行中此条件会升级所有无证明样本，不能从配置存在就声称已节省调用。执行升级后可由Fusion选择高优先级LLM，否则使用便宜节点事实；选择策略仍沿原冻结政策。建议只引用需要参与此路由的节点校准产物，其他节点的覆盖与发布门槛按实际执行评估，不伪造跳过节点输出。

使用原质量/回归门禁验证路由质量，原Trace/ModelGateway记录实际调用/Token/费用。这里不添加估算节省指标、不承诺成本或吞吐改善；须以同数据的基线与级联执行、调用减少和质量不退化证据验收。历史图不含新操作时JSON/行为保持，未切默认v2、未修改Framework或部署。
