# I4 不可变触发尝试历史

## 实施前复用与缺口

TaskExecution 记录已经创建的执行轮次，节点执行 Trace 记录模型/引擎尝试，二者都不覆盖创建 Task 前的 Cron/归档订阅授权与物化失败。框架 Audit 复用 HTTP 操作审计，但 EDA 异步审计不提供调度业务事务提交证据；当前各触发器 lastError 会被下一轮覆盖。本批新增仅保存触发尝试事实的一张追加表，跨 Cron、归档订阅、已接收 Task 的等待物化复用，不复制 Task/Execution/Inbox 或授权模型，不改框架。

每个尝试先独立提交 STARTED，再在域事务内追加 FINISHED；失败在域事务回滚后独立追加 FINISHED。STARTED 不被更新，完成事件也不能被后续重试覆盖。只有 STARTED 的尝试表示结果未确认（例如进程崩溃），不推断失败或成功。

## 事务协议

V1.1.47 的 `iqc_trigger_attempt_event` 使用 attemptId/phase 唯一键，每次后台调用产生新尝试 ID。事件只追加，不提供更新/删除接口；应用不可变约束不等于数据库管理员级 WORM 保证。

- STARTED：在当前帧摘要及负责人范围可验证后、查询 fresh 授权前，通过 REQUIRES_NEW 提交。保存父对象/修订/证据 hash、计划/事件时刻和稳定负责人，不保存输入正文或令牌。上下文最多 8KiB。
- FINISHED / DOMAIN_COMMITTED：域服务和此追加事实共同由 TriggerAttemptRunner 的 RR 事务提交。表示本轮物化/过期/跳过事务已提交，不表示模型检测成功。processedUnits 对 Cron/Task 是处理帧数量，对订阅是本轮接收归档数量。
- FINISHED / NO_CHANGE：没有新的物化结果，例如等待输入、并发帧已失效或本轮没有可接收输入；可能已写入退避信息。
- FINISHED / FAILED：域事务及同步负责人范围退出后，独立事务追加错误类型。只记录异常类，不保存异常消息/正文或授权细节。已经存在的完成事实始终优先，失败处理不会覆盖它。
- UNCONFIRMED：目录读到 STARTED 但没有 FINISHED。包括执行尚在进行、进程中断或完成事实无法追加；不能将其归为成功或失败。

开始历史写入失败时不进行本轮域操作。正向完成历史写入失败会使本轮域事务回滚；失败历史追加也失败则保留 STARTED 并记录服务日志。下一轮新尝试不覆盖旧记录。可读帧之前的配置损坏仍沿既有 lastError/服务日志诊断；本批没有为无法验证归属的坏快照制造尝试身份，也没有将全表发现查询失败误记为某个业务对象的尝试。

## 查询与 UI

`GET /api/iqc/trigger-attempts?kind=PERIODIC|SUBSCRIPTION|TASK&parentId=...&current=1&size=20`，权限 `iqc:trigger:attempts:view`，分页上限 100。服务器先检查父对象可见性，再将事件限定到该父对象；诊断保持私有，非全范围用户还必须匹配原负责人 username 和稳定 userId。不可见父对象不会通过空目录泄露存在性。

只读 RR 事务按开始事实分页，再读取这些尝试的完成事实，生成每尝试一行视图。不会返回完整 Context/负责人授权范围/输入内容。周期、订阅详情与接收 Task 详情复用同一历史组件；当前没有历史的对象显示空列表。

## 边界

该历史覆盖触发物化调用，不替代已有模型/节点执行 Trace 或 TaskExecution。自动模型失败重试/重试策略、全局速率/并发/成本预算仍待实现；本批没有实现未确认尝试自动判死、历史保留/归档或数据库级不可篡改存储。完整 I4/PRD 继续。

没有新增/运行测试、迁移、真实身份/事务/浏览器/模型或部署。真实多实例、故障提交与重启验收尚未执行；编译/构建与只读复核证据见协作交接。

诊断补充：失败事实保存 AUTHORIZATION/EXPIRATION/MATERIALIZATION 阶段、异常类型及既有 IQC 错误目录中的受控错误码，不复制自由文本异常消息。Runner 在调用域服务前核对尝试 Context 与当前帧的类型/父ID/修订/hash/时刻/负责人，禁止把一个尝试的完成事实挂到另一个帧。
