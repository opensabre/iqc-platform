# 四步任务的创建和执行

沿用 `POST /api/iqc/tasks` 与现有任务队列，新增请求组合为 `name`、
`dataSelection`、`processingConfiguration`、`resultProcessing`、`concurrencyLimit`。
新组合不能混用旧的规则、Agent、标签或取数字段。

创建事务冻结已发布的引擎引用与结果处理配置，保存在原有任务快照字段。
批量模式校验所选会话；随机抽样、条件筛选保留条件，首次执行时确定实际名单。
重试沿用已经确定的会话名单。

现有会话工作线程按各操作配置的顺序执行引擎，每个引擎结束后单独提交原始
结果集检查点。引擎失败继续执行后续引擎。输入消息、输出、证据和失败记录
由结果集保留，评分和标签由独立结果处理器产生。

处理后的完整结果写入现有会话结果的 `businessItemResultsJson`，评分沿用
`scoreStatus`、`finalScore`、`scoringResultJson`。结果与消息进度在一个短事务中
提交；过期执行者、取消任务不能提交。暂停在会话边界生效。

新重试批次复用最早已保存输入和上一批次的成功引擎记录，仅重新执行失败或
未执行的引擎；旧批次的失败记录仍保留。外部调用与检查点不是分布式事务，
调用完成而检查点失败时，恢复可能再次调用该引擎。

当前范围是后端创建和执行接线。四步向导组合、原始结果的查询展示，以及标签
结果接入现有查询界面仍需后续实现，不能据此认为整个原型已验收。
