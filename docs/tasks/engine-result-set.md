# 多引擎执行结果集

统一对象 `EngineExecutionResultSet` 的粒度是 **任务 × 执行轮次 × 会话**。质检与打标引擎均进入同一个结果集，按 operation、sequence 区分；同类型的多个实例具有不同 engineInstanceId，每次执行记录独立 engineResultId。这个对象是证据与数据交接契约，不是最终业务结论。

## 结构

```text
结果集（schemaVersion / resultSetId / taskId / executionId / conversationId）
├─ input：执行时的原始会话快照，含消息 ID、顺序、角色、时间、完整文本
├─ taskConfiguration：本次固定的任务、引擎与结果处理配置（凭证保持引用）
└─ engines[]：全部引擎结果；不同输出不会覆盖
   ├─ engineResultId / operation / engineInstanceId / engineType / sequence
   ├─ configuration：该引擎实际参数和依赖版本
   ├─ startedAt / finishedAt / status
   ├─ rawOutput：原始引擎输出文本，解析失败仍保留
   ├─ observations[]：目标、状态、类型化值、置信度、原因、证据引用
   ├─ evidence[]：证据 ID、原消息 ID、起止偏移、原文
   └─ failure：错误码和说明；失败记录仍属于结果集
```

`rawOutput` 是引擎响应内容，不包含 HTTP Authorization、API key 等传输凭证；正则/DLS 将其真实匹配输出序列化保留。不能用汇总结果或重新生成的结构化结果冒充原始输出。调用前失败可无 rawOutput，仍保留配置、状态和失败原因。存储失败不等于引擎失败，不能吞掉后继续假成功。

原始输入只固定一次，证据精确引用该快照，使用 Java/JavaScript 的 UTF-16 下标、左闭右开；构造时检查引文与区间确实来自该消息。没证据的判断可保留，但不能编造消息或引文。需要异常输出审查时，原始文本仍在 rawOutput；非法证据不会包装成有效结构化证据。

## 交给结果处理器

执行器完成本会话全部引擎后，持久化结果集和全部原始引擎记录，再调用 `TaskResultProcessor`。评分处理器、标签处理器分别消费同一个只读结果集及自己的处理配置。不需要不同引擎预先协商成一个结论，也不在执行器中做覆盖、选优或扣分。

派生结果 `ProcessedResult` 单独记录处理器编码/版本、来源结果集 ID、参与处理的引擎结果 ID 列表、业务输出。业务输出中的每个质检项/标签还应关联具体引擎结果、观察目标和证据；不能只留下总分。处理器只能产生新结果，不能改写原始集合。重新处理时保留旧派生结果和对应处理配置；不需要重新调用引擎。

评分/标签处理器具体汇总规则属于结果处理配置：例如质检项如何从全部观察计算判定和分值、标签如何从多个类型化值生成结果。执行顺序不自动代表处理优先级。用户未选定的规则不硬编码为“后者覆盖”或“优先级取胜”。

## 数据选择及重试

批量选择保存明确名单。随机抽样和条件筛选在**执行时**取数；数量不足有多少处理多少，无数据按 NO_DATA 表达。模拟执行只预览，不锁定正式名单。开始一次正式执行后固定本次实际名单及原始输入，恢复同一次执行不重新取数、不随机重抽。

对失败引擎保留记录并继续后续引擎；取消任务时尚未执行的引擎记录 SKIPPED 及原因。部分失败仍交付完整结果集，由结果处理模块表达可处理结果及缺口。不同正式执行使用不同 executionId，不能覆盖历史。未来新增小模型仅扩展引擎适配与类型，本轮不提供空实现。

## 复用与当前状态

复用 IQC main 的会话、任务、执行、正则、DLS、LLM、评分和标签能力。已有 `InspectionResult` 是业务/规则结果，不具备独立引擎实例、原始输入快照及完整失败维度，因此引入本契约而非强改其历史语义。没有框架或基础服务修改。

当前交付为可序列化的不可变协议与处理器边界；不宣称执行器和持久化接线已完成。引擎结果按会话汇集；最终落库、适配器原始响应捕获、处理器实现将作为后续独立小 PR 接通。

## 顺序执行与检查点实现

`MultiEngineExecutor` 接收每个操作的引擎实例计划，按各自 sequence 执行。适配器返回原始输出、结构化观察与证据；解析失败应带原始输出和 failure 返回。非法证据会转为失败记录，保留 rawOutput，并继续后续引擎。

调用首个引擎前先保存输入快照，每个引擎返回后再保存完整检查点。`EngineResultSetStore` 使用 IQC 自有表 `iqc_engine_execution_result_set`，JSON 保存完整契约，执行轮次与会话唯一，revision 乐观锁防止并发覆盖。历史引擎记录只能追加；相同检查点重复保存不增加版本。短事务独立提交，不跨越外部引擎调用。

恢复执行必须加载原检查点，校验配置一致，并跳过已经记录的引擎（包括失败记录）。存储异常直接向上传播，不能当成引擎失败继续调用。引擎已经返回但检查点未提交时，恢复可能再次调用该引擎；本实现不承诺外部调用恰好一次。取消后未调用的引擎记录 SKIPPED。

新增迁移 V1.1.33 仅作用于 IQC 数据库。H2 的 MySQL 模式用于本地约束与读写验证；真实 MySQL 的 Flyway 验证由现有 PR migration CI 执行；基础结果集 PR #60 的 Flyway MySQL 与 Maven Verify 已通过。

当前已增加可调用的执行协调器与存储服务；任务队列入口、具体 REGEX/DLS/LLM 适配器及最终评分/标签处理器仍需后续接线，不等同于向导或完整任务模块已经可用。

## 正则适配器

`RegexEngineAdapter` 复用现有 `RuleMatcher` 的 REGEX 匹配语义，参数为 `targetId`、`expression`、可选 `speakerRole`。按快照消息逐条评估，每条消息记录首个匹配（与现有匹配器一致），rawOutput 是真实评估得到的逐消息 JSON 数组，包括未命中行。正则实例只输出目标是否匹配及来源证据，不把命中自动解释为扣分、违规或最终标签。

有适用消息但未命中输出 DETERMINED/false；没有符合角色的消息输出 UNKNOWN/null，避免将缺少输入误判为否定。证据偏移使用 UTF-16，零宽匹配保留真实输出但不生成空引文。配置或正则语法错误由执行协调器记录为失败，继续后续实例。

此适配器可直接交给 MultiEngineExecutor.Step 使用。尚未新增任务创建接口、队列接线或用户可操作页面；DLS 与大模型适配器也不由此 PR 宣称完成。

## DLS 适配器

`DlsEngineAdapter` 参数为 targetId 与创建时固定的 DLS expression。复用现有 DLS 1.0 编译与完整会话求值，不将跨消息规则拆成逐消息执行。保留原生 Evaluation 的完整 JSON（含定义名、消息索引、区间和原因），并将非空原文区间投影为标准证据；证据仍由结果集校验。

未满足跨消息顺序输出 false；空会话输出 UNKNOWN/null。DLS 语法错误作为该实例失败记录，后续引擎继续。此适配器不自动评分、生成标签，不另建 DLS 语言或规则表；任务创建/队列/四步向导接入仍是独立后续工作。
