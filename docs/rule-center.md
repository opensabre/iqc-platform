# 专业规则中心

## 能力分层

- 原子规则：包含、禁止包含、必须包含、正则、精确比较、前后缀、结构化条件和 LLM 语义判断。
- 结构化规则：兼容以 `COMPOSITE` 类型保存的历史数据，通过 `all`、`any`、`not` 递归组合单条消息的字段条件；它属于规则库，不是独立的跨规则组合层。
- DLS 会话规则：从 XLSX 导入词槽、子规则和最终规则，支持角色、排除、顺序与消息距离，并返回可解释证据链。
- 规则集：有序引用已发布规则，具有独立版本、审批与发布生命周期，可被质检任务稳定引用。

历史 `KEYWORD`、`REGEX`、`STRUCTURED`、`LLM` 规则继续有效。规则测试与质检执行使用同一个
`RuleMatcher`，防止配置页测试与任务执行产生语义漂移。

DLS 规则使用独立的会话执行器，语言契约、导入格式和限制见 [DLS 规则引擎](dls-rule-engine.md)。导入
只创建草稿，仍需经过测试、提交审批和发布，发布后可加入规则集并随 Agent 任务快照执行。

## 组合表达式

```json
{
  "all": [
    { "field": "content", "operator": "contains", "value": "收益" },
    { "not": { "field": "content", "operator": "contains", "value": "风险" } }
  ]
}
```

字段包括 `content`、`speakerRole`、`sequenceNo`、`relativeTime`。操作符包括文本比较、多值包含、
正则、数值比较和文本长度比较。单组最多 100 个节点，表达式最多 16000 字符，不允许执行脚本。

## 规则集与任务快照

规则集只允许发布时引用已发布规则。任务使用规则集时，服务端把规则集 ID、版本、聚合模式和完整规则
内容写入 `rule_snapshot_json`；后续修改规则或规则集不会影响历史任务。

- `ALL`：所有成员均命中时，规则集结果命中。
- `ANY`：任一成员命中时，规则集结果命中。

未使用规则集的历史任务仍保存规则数组，并沿用任一规则命中的兼容语义。

## Agent 质检模式

Agent 配置中的 `mode` 决定规则执行编排：

- `RULE_ONLY`：只执行关键词、正则和结构化等本地规则，不调用 LLM。
- `RULE_THEN_LLM`：先执行本地规则；只有本地规则命中候选时才调用 LLM，并将候选规则及证据作为结构化上下文传入。LLM 否定时，本地命中状态降为 `CANDIDATE`，不参与最终命中评分。
- `AGENT_LLM`：跳过本地规则，由 LLM 规则结合 Agent Prompt、Skill、MCP 和模型快照执行；没有配置 LLM 规则时，使用 Agent 综合质检入口。

`AGENT_LLM` 会在每次模型请求内按已发布快照连接 MCP Server，只向模型暴露 `allowedToolsJson` 白名单中的工具；空数组表示禁止全部工具。工具名以 `<serverCode>__<toolName>` 暴露，模型发起调用后，结果作为工具消息回送模型，再由模型给出最终质检 JSON。MCP 客户端在本次模型请求结束后关闭。`BEARER` 密钥解析结果作为 Token；`HEADER` 密钥解析结果必须是请求头 JSON 对象（例如 `{"X-API-Key":"..."}`）。

未显式配置 `mode` 的历史任务沿用旧版规则并列执行语义。

## 发布流程

规则和规则集均遵循：创建草稿 → 提交审批 → 审批发布。已发布内容通过新版本演进，不直接覆盖历史
版本。管理端分别提供规则库、会话规则、规则集、测试中心、审批与发布子菜单。规则库管理单消息规则，
会话规则管理 DLS；DLS 内部 SLOT、RULE 和 ENTRY 均为文档私有定义，不进入普通规则库。

## 统一判定与证据层级

任务按会话执行。每条已发布顶层规则在一个会话中只产生一个规则判定并最多扣分一次：单消息规则扫描
会话内适用消息后汇总命中，DLS 对完整会话执行一次。两者的命中位置均作为消息证据附属于规则判定。
规则集的 `ALL` / `ANY` 聚合规则判定生成会话结论，任务再聚合会话结论。

```text
任务结果 → 会话结果 → 规则结果 → 消息证据
```

SLOT 和 DLS 内部 RULE 只用于解释 DLS 证据链，不产生独立扣分结果。
