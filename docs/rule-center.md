# 专业规则中心

## 能力分层

- 原子规则：包含、禁止包含、必须包含、正则、精确比较、前后缀、结构化条件和 LLM 语义判断。
- 组合规则：以 `COMPOSITE` 类型保存，通过 `all`、`any`、`not` 递归组合消息字段条件。
- 规则集：有序引用已发布规则，具有独立版本、审批与发布生命周期，可被质检任务稳定引用。

历史 `KEYWORD`、`REGEX`、`STRUCTURED`、`LLM` 规则继续有效。规则测试与质检执行使用同一个
`RuleMatcher`，防止配置页测试与任务执行产生语义漂移。

## 组合表达式

```json
{
  "all": [
    { "field": "content", "operator": "contains", "value": "收益" },
    { "not": { "field": "content", "operator": "contains", "value": "风险" } }
  ]
}
```

字段包括 `content`、`speakerRole`、`sequenceNo`、`relativeTime`。操作符包括文本比较、多值包含、
正则、数值比较和文本长度比较。单组最多 100 个节点，表达式最多 16000 字符，不允许执行脚本。

## 规则集与任务快照

规则集只允许发布时引用已发布规则。任务使用规则集时，服务端把规则集 ID、版本、聚合模式和完整规则
内容写入 `rule_snapshot_json`；后续修改规则或规则集不会影响历史任务。

- `ALL`：所有成员均命中时，规则集结果命中。
- `ANY`：任一成员命中时，规则集结果命中。

未使用规则集的历史任务仍保存规则数组，并沿用任一规则命中的兼容语义。

## 发布流程

规则和规则集均遵循：创建草稿 → 提交审批 → 审批发布。已发布内容通过新版本演进，不直接覆盖历史
版本。管理端分别提供规则库、组合规则、规则集、测试中心、审批与发布子菜单。
