# DLS 规则引擎

## 目标

DLS 用于承载由词槽、子规则和最终质检项组成的确定性会话规则。Excel 导入后，每个非空工作表生成一条
`DLS` 类型草稿规则；规则继续使用规则中心现有的版本、审批、发布、规则集和任务快照能力。词槽和子规则
属于当前 DLS 文档的私有定义，不单独创建 `iqc_quality_rule`，不能跨 DLS 引用，避免污染可选质检项列表
并保持文档可独立复制、版本化、发布和回滚。同一 SLOT 可以被当前文档内的多个 RULE 引用。

## 版本 1 兼容语义

导入文档保存 `languageVersion: "1.0"`。版本 1 对样本文件使用的操作符定义如下：

| 语法 | 含义 |
|---|---|
| `a;b` | 任一候选项命中 |
| `[slot_x]` | 引用词槽，并展开为非捕获正则组 |
| `[rule_x]` | 引用子规则的命中事件 |
| `a&b` | 两个规则都命中 |
| `!a` | 在当前距离窗口内排除规则 a |
| `a%b` | a 在会话中先于 b 命中 |
| `a~b` | a、b 在同一消息内按文本顺序命中 |
| `(a&!b)<N>` | a 命中，且前后 N 条消息内 b 未命中 |

裸写的 `rule_x` 也按规则引用处理，用于兼容“以贷养贷”和“抹黑行方”工作表。所有 Java 正则在导入
预检时编译；缺失引用、重复定义、循环引用、非法正则和无法识别的表达式都会阻止创建草稿。

## 文档与执行边界

DLS 表达式保存为 JSON，包含来源、工作表、定义列表和最终入口表达式。任务创建时沿用现有规则快照，
所以历史任务不受后续规则库更新影响。执行时以完整会话作为输入，先计算词槽，再计算子规则，最后计算
入口表达式；结果包含命中的消息、字符区间、定义名称和文本证据。

在 `RULE_ONLY` 模式下，DLS 作为本地确定性规则执行。在 `RULE_THEN_LLM` 模式下，DLS 命中作为候选
证据传给质检智能体复核。在 `AGENT_LLM` 模式下仍遵循现有约定，不执行本地规则。

## Excel 导入契约

- 仅接受 `.xlsx`，单文件最大 10MB，不支持宏和外部链接。
- 每个非空工作表最多 1000 行；A 列为名称、B 列为表达式、C 列为目标角色。
- `slot_` 行是词槽，`rule_` 行是子规则，最后一个其他名称行是最终质检规则。
- 没有最终质检规则的工作表只做诊断，不创建可发布规则。
- 默认过滤名称以 `slot_测试` 或 `rule_测试` 开头的测试定义，并同步移除入口引用。
- 导入只创建 `DRAFT`，不得自动提交或发布。

## 安全和限制

DLS 不执行脚本。正则表达式长度、定义数量、引用深度、会话消息数和单条消息长度均有限制。运行时应
复用发布时的编译结果缓存；遇到运行错误时返回诊断结果，不能静默降级为命中。

样本文件没有提供旧系统对 `%`、`~` 和 `<N>` 的正式规范，因此版本 1 语义是基于表达式结构建立的
兼容契约。上线前必须使用脱敏的正反例会话进行回归，确认与旧系统输出一致。
