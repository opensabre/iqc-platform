# V2 检查与标签联合输出：实现边界

状态：截至 2026-10-04，本地联合标签从草稿试跑、正式发布到普通发布模板任务的执行与结果物化已打通，包含逐项路线联合标签；H2 实际事务用例通过。真实模型、业务样本、生产数据库、网关和混合版本尚未验收，本地实现不等于可上线。

## 改造前基线与缺口（实施进展见下文）

| 边界 | 已有能力 | 缺口 |
| --- | --- | --- |
| `scheme/SchemeDefinition`、`SchemeDependencyResolver` | 冻结质检项、明确规则版本、独立评分 | 无标签引用，只展开质检项规则 |
| `label/LabelResolutionService` | 标签/集合选择、数据范围、版本号、绑定和值定义快照 | 当前实体没有历史版本表；不能以版本号查询历史定义 |
| `task/InspectionTaskService` | `labelScopeSnapshotJson` 及已有标签任务入口 | 方案创建未设置标签快照；兼容入口明确禁止规则与标签联合选择 |
| `result/HierarchicalResultService` | 单次规则结果供评分和标签投影使用 | 标签投影异常会回滚整个会话结果；不符合非计分标签错误不阻止检查评分 |
| `label/LabelResultService` | 写入既有标签结果表，不二次调用检测器 | 仅输出 HIT、首个绑定命中后退出、提取缺失可取默认值，没有覆盖/冲突/主体契约 |
| `label/LabelResultQueryService` | 任务范围、最新会话结果、冻结名称、证据查询 | 单一来源规则，未知/冲突覆盖及多来源证据尚未表达 |

## 不变原则

1. 不新建标签字典、标签集合或平行结果表。复用现有标签定义、任务快照、会话结果、标签结果与证据表。
2. 不改变旧 schema 1.0 标签任务的解释，不回填历史结果。新语义必须显式标记版本；旧格式与新格式不得静默混用。
3. 状态为 KNOWN / UNKNOWN / CONFLICT / ERROR。明确否认是 KNOWN 且布尔值 false，不另造 NEGATED 状态；未命中不是 false。
4. 检查评分仅消费方案评分项。标签专属规则不计分；共有规则版本只执行一次。发现同一规则引用不同版本时明确拒绝，不能任选其一。
5. 不从默认值生成确定事实。KNOWN 必须有合法值、明确主体及同会话证据；第三方转述、假设和主体不明不能当作当前客户事实。
6. 检测失败不得写成 UNKNOWN，更不能写成通过。完整的已评估但无可靠事实才是 UNKNOWN。没有目标说话人、存在未映射角色与目标发言但未提及，必须给不同原因；未知主体不能冒充目标。冲突保留所有候选和来源，不选首条。

## 实施顺序与验收门槛

### A. 方案配置和冻结依赖

- 在既有方案定义增加可选标签引用，缺省不序列化，维持历史摘要及复核基准。现有构造调用保持兼容。
- 专家选择现有已发布标签；集合仅作为选择工具，发布时展开为具体标签。解析时验证标签可见性及版本，读取完整定义/绑定/值域并冻结到发布快照。
- 标签当前记录变成新草稿后，不得让旧任务重新解析成新定义。启动时只检查可用性，业务内容始终来自冻结快照。不能直接复用当前 `resolve` 的版本重解析作为启动校验。
- 合并明确版本的检查与标签规则，并将完整标签快照写入现有任务 `labelScopeSnapshotJson`。标签内容必须参与试跑/发布摘要和完整性校验。
- 任务创建、排队、恢复和工作线程启动时均执行冻结投影校验：执行规则须等于发布依赖、标签快照须等于冻结定义，每个绑定规则/标签值须有唯一同主体目标。正式发布与普通任务复用同一冻结协议，并保留路由/主体/值域校验。
- 门槛：旧快照原样往返；同规则同版本去重、不同版本拒绝；无权/未发布标签拒绝；修改当前标签不改变旧任务。

### B. 有覆盖、有证据的结果

B2 内部物化分支已接入会话结果事务：schema 2.0 每个值定义写入 `iqc-label-result-v2` 状态，保留明确 false、多候选及其规则来源；完整空事实为 UNKNOWN，冲突为 CONFLICT，缺失协议、损坏事实和检测错误为 ERROR，不读取默认值。输入事实必须显式使用 `iqc-label-facts-v2`，包含 labelId/valueCode/ruleId、subjectKind/subjectRole、value、evidence（messageId/text）。结构或版本错配直接失败，数据库异常仍交给外层事务回滚。隔离 H2 上的实际 Spring 事务与 MyBatis Mapper 回归已验证标签插入失败时会话、规则、证据和标签同时回滚，以及同执行重试不重复写入；真实 MySQL 事务与并发仍待验证。

联合草稿试跑中的标签检测若返回空 finding，会在规则观察中记录 `MISSING_FINDING`，标签值输出 ERROR；同一会话已完成的质检项仍保留独立评分。此业务错误与证据/结果写库失败不同，后者仍回滚会话事务。

新版物化入口在任何写入前校验冻结标签主体为 `user/customer/agent`、值类型受支持，且标签 ID/值编码为文本；损坏快照不能因检测器返回空事实而落成 `UNKNOWN`。此校验是结果链路的失败关闭补强，不替代任务启动时的冻结投影核对。

方案结果物化还会按规则运行角色检查适用消息覆盖：缺少检测切片时写入明确的 `NOT_EVALUATED / MISSING_OBSERVATION`，标签输出 ERROR，不把已有候选当作整段会话已覆盖。会话级 LLM 允许在一个角色的承载消息上引用另一个角色的原文，不要求引文消息重复承载同一规则观察。

边界：当前仅验证声明主体、证据消息归属和原文子串，不证明引文语义支持候选值；否定、假设、转述仍需检测器与会话级 LLM 契约及实测。候选来源存于 valueJson，旧 sourceRuleResultId 仅作为兼容锚点；前端多来源证据展示已接入。`V1.1.29` 准备将逐消息事实/证据及标签候选值的存储列从 TEXT 扩为 MEDIUMTEXT，但迁移实跑、上限规模和真实数据库事务测试尚待完成。正式发布门禁不解除。

B3 查询/导出已接入：既有标签结果接口附加 `status`（旧任务 HIT，新任务四态），按全部候选来源查询既有证据表，并先验证来源属于当前 canonical 会话结果；无候选时不展示兼容锚点的无关证据，数据库查询失败不再吞成空证据。新版查询还以来源、消息 ID 和引文原文过滤证据，避免共享规则下其他标签的引文混入；候选引文找不到对应持久化证据时显式失败。候选原始引文仍在 valueJson 内，检测器证据写入与候选引文的一致性尚需真实数据库端到端验证。XLSX 保留全部状态行，输出真实状态及完整值/候选 JSON，不再统一写 HIT；超过 Excel 单元格上限的证据和候选 JSON 转入同一工作簿的 Base64 UTF-8 分片明细，主表保留行列定位，容量超限明确拒绝。单任务与仪表盘统计只将旧 HIT 或新 KNOWN 算入检出，KNOWN false 表示有确定识别结果而不是正向画像；UNKNOWN/CONFLICT/ERROR 不进入检出分子，全部会话仍在分母。专家联合试跑的四态计数、冻结范围覆盖摘要及结果深链已用全拦截合成 API 的真实 Chromium 验收；真实后端、数据库与模型联调仍待完成。

联合方案任务的标签结果查询现在还校验任务标签范围与冻结发布依赖完全一致；缺失或篡改的范围、错版本结果及重复结果明确失败，不能以当前标签目录名称或静默去重掩盖覆盖缺口。联合任务的结果明细与跨任务汇总也强制要求 `iqc-label-result-v2`，空值、旧协议或损坏 JSON 不得降级为兼容 `HIT`；旧协议任务仍保留其原读取兼容行为。

新版结果读取还复用试跑发布的载荷结构契约：状态、确定值、候选值与引文结构必须一致；联合任务必须匹配冻结的值编码、类型和主体。损坏的 `KNOWN`、虚假的 `CONFLICT` 等不会计入汇总，也不会在明细中冒充已确认画像。此校验不替代来源规则结果和持久化原文证据的归属核对。

单任务与首页跨任务“标签洞察”都核对联合任务冻结范围，并使用冻结标签/分组名称；错版本、重复结果或缺失任务不再悄悄进入汇总。旧任务沿用现有目录统计。这里的“确定识别”仍包含 KNOWN false，不等于正向画像命中。

两处洞察汇总另返回 `coverageValueCount` 与 `coverageStatusCounts`，展示 UNKNOWN / CONFLICT / ERROR 值记录率。分母为查询范围内已生成的 `iqc-label-result-v2` 标签值行；旧 HIT 和本应生成却缺失的值均不进入，不能把这些状态率解释为完整覆盖率。确定结果率仍按已生成会话数计，口径与值记录率不同。

首页跨任务确定结果率按“任务 ID＋会话 ID”评估次数计数，同一会话在两个任务中不去重；同一任务内只采用所选时间范围内最新的 canonical 会话结果，因此仍不是按全部执行轮次的趋势统计。这里的“最新”以已有执行实例的 `attempt_no` 为先，缺少执行实例的历史行才以创建时间和结果 ID 兜底；时间窗口先筛选结果，再在窗口内按此顺序选一条。单任务汇总沿用本任务会话口径，两个比例都不表示独立客户数。

部分会话失败后可仅重试未完成消息；后续会话结果按执行轮次判断当前结果，成功会话仍引用之前成功轮次。专家发布校验、结果页、批次导出、业务报告与复核当前性校验采用同一顺序，避免旧失败结果在时钟偏移时覆盖已恢复结果。隔离 H2 已覆盖“旧失败结果时间更晚，恢复后仍通过发布前校验”的路径；真实 MySQL 与跨节点并发仍未验证。

前置改造已接入：方案规则结果的 `findingJson` 使用 `iqc-rule-observations-v2`，保存每个规则切片的 messageId、status、原始 finding；损坏 finding 标记 INVALID_JSON，空观察数组表达没有检测切片。旧任务仍保留首条命中的原格式。该封装只是信息保留，不是已验证标签候选：原始 finding 可能包含其他规则的内容，后续不能递归随意提取并当作当前规则证据。

- 在 `LabelResultService` 增加显式新版分支，复用 `InspectionLabelResult.valueJson` 承载版本化状态、原因、主体、值、候选及来源引用；是否确需索引列由实际查询需求决定，不预先新增表。
- 每个被选择的识别目标都有结果，不能仅落命中项。多来源证据复用现有证据记录，以明确 ID 关联；查询不得仅按单一 `sourceRuleResultId` 丢弃冲突来源。
- 原子布尔值和已有受支持值类型先接通；没有受控枚举类型之前，不宣称职业枚举已完成。LLM 主体识别和会话证据契约属于同一验收链，不能以简单关键词命中替代。
- 可预期的检测/提取错误落为 ERROR，并保留机器评分；数据库写入失败或损坏快照仍应失败，不能宽泛吞异常假装成功。
- 门槛：false 保留、未提及未知、冲突不取首个、格式错误为 ERROR、证据跨会话拒绝、非计分标签失败不影响最终评分、重复物化不多写。

### C. 发布、查看、导出和新手入口

C1 前端只读适配已接入现有任务结果页：状态、最终值、主体、全部候选与逐条引文定位，false 显示“否”，冲突/错误不提升候选为确定值；历史任务标注兼容命中。页面列出已返回标签值记录的状态计数（不是未产出结果的覆盖统计），明确确定结果率包含否认。前端损坏格式显示错误；批次切换清除旧结果并忽略旧请求回包。该适配不包含模板标签选择、检测器输出或真实环境联调，不解除执行门禁。

- 专家方案表单引用现有标签选择器；普通用户不再维护标签或规则，只查看模板输出说明。
- 试跑同时展示检查与标签覆盖；正式发布需确认两类输出，不允许只检查评分通过而忽略未执行标签。
- 结果页将画像与评分分区，展示状态、主体、候选和证据；沿用权限与任务范围。
- 标签导出包括未知/冲突/错误，不只导出正向命中；统计分母明确。候选自动扩展默认关闭。
- 门槛：同一模板一次执行可见独立分数和完整画像；真实角色正反权限、旧任务兼容、失败重试和导出一致性。

## 与会话级 LLM 的依赖

Provider 扩展取舍：现有 `LlmQualityProvider` 仅有字符串话术，无法保留会话身份、消息 ID 和角色；不另建模型服务或框架 Starter。在该接口增加显式会话方法，Spring AI 实现复用现有路由、Agent、限流、计次及重试。消息内容逐条脱敏，身份字段不作为文本整体脱敏，避免证据 ID 被改变；无效、跨会话、重复 ID、超限输入拒绝而非截断。其他适配器缺省返回不支持，不降级为单消息执行。执行器内部已调用会话方法；任务标签快照和正式发布仍受门禁保护，不能据此宣称会话级质检已上线。

依赖解析已从冻结标签生成每条规则的 `labelFactTargets`：只有明确绑定该规则的标签值进入目标，包含标签/规则版本、值编码/类型/说明、当前参与人及 user/customer/agent 主体。现有标签目录的客户角色为 `user`；事实主体须与原始消息角色精确一致，不做隐式改写。旧标签 defaultValue 不进入事实或模型目标，不允许据默认值补事实。要求每个联合标签有 1–10 个受支持值定义、编码唯一且主体明确；`all` 必须先由专家明确识别对象。无标签规则缺省不写新字段，保留旧快照形状；同版本共享规则仍只展开一次。发布版任务的依赖校验已使用冻结标签快照，并继续检查规则、Agent 和受管资产可用性。可定位普通规则另从标签值 `configJson.onRuleHit` 冻结显式命中值；模型规则不读取它。

执行器内部已加入本次会话、每条识别规则、每个配置轮次的临时 LLM 调用复用。消息观察保留每条规则自己的原始 finding；只有首次适用的消息承载会话事实，其他消息保留显式空事实，防止同一候选被复制为多个来源。检查 hit 与标签 false 分开，模型即使返回 `hit:false`，合法标签引文仍写入既有证据表。标签证据写库错误抛出，交由会话结果事务处理。可定位普通规则显式映射已接入内部执行与证据契约：未命中为 UNKNOWN，命中但片段不可定位为 ERROR，不自动推断正负。此缓存仅限当前进程中的一次会话处理；重试、跨节点、模型输入脱敏引用和 DLS/结构化规则事实映射仍需完整验收，联合执行门禁保持。

现有方案 LLM 检测仍按消息复用。标签语义要求主体和跨消息冲突时，必须接入完整会话输入、稳定消息 ID 和受验证证据。不能将首期闭环缩减成关键词标签并宣布完成；需要分别证明规则原子事实路线与会话级 LLM 路线。

TXT/API 的明确中文角色别名现于接入时归一；旧会话只在执行内存中归一，不回填数据库，原始 TXT 行仍保留。`customer` 保持既有独立角色，未知角色不猜为客户或坐席。联合标签真实试跑前仍需验证未知及第三方消息的主体归属与 UNKNOWN/ERROR 解释，不因别名修正而撤除门禁。

## 发布边界

新建联合方案任务的冻结协议使用 `iqc-scheme-v2-joint-v1`，同时包含适用条件时仍使用联合标识；专家编辑格式保持 `iqc-scheme-v2`。当前读取器保留旧标识联合任务兼容，历史内容与摘要不重写。正式发布前校验先核对试跑任务实际冻结内容摘要，再仅归一受支持协议标识后严格比较全部冻结字段；规则、标签、评分及额外字段不能在归一中被忽略。实际旧实例拒绝行为及混合版本升级仍需独立验证。
