## 复用与边界

- 保留 IQC 的 agent、skill、modelprofile、mcp 数据模型和既有接口，不新建平行资产中心。
- 智能体版本比较/回滚、Skill 历史优先接入已有服务和接口，避免重复实现。
- 模型连接测试复用 `ModelConnectionTestService`；密钥解析复用 `SecretReferenceResolver`，不另建凭据库。
- MCP 管理连接验证和工具发现存在管理接口缺口：先检查 `SnapshotMcpToolProvider` 的客户端生命周期、超时及认证处理，决定最小提取/复用方式，再实现 IQC 内的管理接口；不修改框架。
- 关联影响查询先复用当前配置及版本快照；区分当前可选依赖和历史冻结引用。确认查询规模前不增加关系表。
- 已检索 Wiki、框架及 base-organization/base-sysadmin Java 源码，未发现可直接替代 IQC 资产模型的实现。权限、审计、字典继续使用既有公共能力。
- 生产导航优先使用授权菜单，单改前端静态菜单不能保证顺序生效。需定位 IQC 菜单初始化/迁移脚本；若涉及 base/shared 服务变更，先给出具体差异并取得用户明确批准。
- 旧配置模式和任务执行策略属于兼容性约束，本阶段不顺带迁移或重定义。

## 已确认的领域边界（2026-11-04）

用户确认：大模型只是任务执行中的一个引擎。智能体管理只管理大模型引擎及其能力，不拥有普通规则、正则规则、规则集和任务执行编排。

- 新建和创建智能体版本时移除质检模式、普通规则、正则引擎、规则集，以及规则和 LLM 的先后顺序配置。
- 智能体保留模型、备用模型、提示词、Skills、MCP 和能力版本。Skills/MCP 是模型可使用的扩展能力，不承担普通规则引擎或任务编排。
- 普通规则和正则继续归属规则中心；后续在任务创建中选择引擎并配置规则、调用顺序、组合策略和最终业务处理。
- 智能体不决定最终评分、规则执行、任务路由或业务结论聚合；模型返回交由任务业务层解释。
- 不仅隐藏前端控件：新建配置契约和服务校验也必须禁止规则及编排字段；新建智能体不能绕过页面创建成普通规则引擎。
- 已发布历史版本不静默改写。历史混合配置的查看、继续执行和迁移方式单列兼容任务；不能让旧版编辑入口继续新增混合配置。
- 当前其他开发分支已有 schema 3 的部分拆分，但仍有旧版编辑和服务兼容逻辑；不能视为 main 已完成，也不直接合入整套其他业务变更。

### 新增前置任务 T0：解除规则与智能体耦合

1. 从 main 建立独立工作区，对照当前分支的相关差异，仅复用必要改动。
2. 前端创建/新版本向导删除模式与规则集选择，停止请求规则集；配置摘要改为模型能力摘要。
3. 后端新建/新版本契约限定为 LLM 能力，校验必须存在主模型；拒绝规则模式和规则集字段，保留资产冻结及审批能力。
4. 检查运行入口，不允许从新智能体配置推导任务执行策略；任务编排的功能建设作为后续任务，不在此处补造默认规则策略。
5. 梳理历史版本被任务引用的情况，明确兼容适配与迁移边界，不删除规则资产或改写已发布快照。
6. 验收：新建及新版本 UI 无规则选项；请求不含规则/编排字段；绕过 UI 的非法请求被拒绝；模型/Skills/MCP 仍可配置发布；历史行为有明确验证结果。

此边界优先于前文能力盘点及原有“模式兼容”约束。T0 在菜单及能力扩展前实施；任务侧引擎编排后续单独分解。

## 已确认需求：智能体测试聊天（2026-11-05）

智能体需要提供聊天式测试入口，用户可与当前智能体进行多轮交互，以验证其行为是否符合预期。该能力纳入第一期，不再作为第二期候选。

### T8：智能体测试聊天

- 入口：智能体列表操作与配置页面提供“测试聊天”，明确展示当前测试的智能体、版本及草稿/发布状态。
- 配置：使用当前智能体的主模型、备用模型、提示词、Skills、MCP 及工具白名单。已保存版本使用其对应配置；未保存配置测试使用明确标识的临时配置，不隐式保存或发布。
- 交互：支持多轮消息、生成中状态、重新开始会话和清空上下文。切换智能体或配置后重新开始会话，避免旧上下文污染验证结果。
- 反馈：展示模型回复、调用结果及必要的耗时、实际使用模型和工具调用信息；失败时区分配置错误、模型调用失败、工具调用失败与超时。不展示密钥或模型内部推理过程。
- 边界：测试走实际模型及能力执行链路，不用模拟回复；不执行正则/普通规则，不创建质检任务，不计算业务评分。MCP 测试可产生真实工具调用，工具授权及白名单与正常执行一致。
- 权限：区分查看、编辑、测试权限；后端校验测试访问权限与资产可用性，不能仅靠按钮隐藏。具体权限编码在接口设计时确定。
- 会话：第一期不新增聊天历史持久化模型；会话上下文的传递、长度限制与隔离在接口设计中明确。是否长期保存测试记录后续单独规划。

实施分解：

1. 检索现有模型调用、流式响应、会话上下文和工具执行能力，记录可复用部分及业务耦合缺口。
2. 定义 IQC 内的智能体测试契约：配置来源、消息、会话边界、响应和错误；复用现有模型路由、凭据解析和 MCP 执行能力，不经过规则或任务编排。
3. 实现后端测试入口及权限、输入限制、超时和错误处理；不依赖真实质检任务 ID 才能发起测试。
4. 实现测试聊天面板，支持当前配置测试及多轮交互，清楚标识测试对象和配置状态。
5. 验证多轮上下文、提示词生效、Skills/MCP 参与、白名单限制、配置切换隔离、权限不足及模型/工具失败场景。

依赖：T0 的纯 LLM 能力契约，以及 T3/T5/T6 中对应配置和执行能力。T7 联调须覆盖 T8。第一期调整为 T0、T2–T8；运行统计与长期测试记录仍为后续范围。
