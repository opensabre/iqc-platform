## 第十三批 B149：IQC 角色权限迁移长资源 ID 升级回归

- `InspectionScoring`：独立扣分制/得分制、评分项目唯一性、无适用项/仅标签无分数、未评估/错误/待复核不生成最终分数、一票否决、计分明细和覆盖数量。
- 此内核不读取规则 deduction/veto，不改变历史分数。旧任务仍走旧评分；新方案快照任务的业务计分见第三批。

兼容接口暂不允许同时指定规则和标签范围：仅合并依赖会使标签规则参与旧评分，因此在方案级评分接入前显式拒绝，不能宣称检查与画像联合输出已经完成。

## 第二批：业务方案版本底座（后端内部能力）

- 增加业务方案主记录及不可变发布记录，不复制规则、Agent 或标签主数据；数据库增量为 `V1.1.25`，冻结基线不变。
- 方案草稿包含业务质检项、明确版本的检测规则引用、命中语义和独立评分政策；禁止评分项引用不存在的质检项。
- 草稿修订号防止过期页面覆盖；编辑与发布锁定同一方案主记录，同一草稿重复发布返回原版本。
- 发布锁定规则及 Agent 已发布版本，保存完整快照和 SHA-256 摘要；检测快照去除旧 deduction/veto 的计分影响，原规则记录不变。
- 编辑草稿不修改当前发布指针；模板读取已发布版本的名称和内容，不泄漏新草稿。
- 纯规则方案不要求 Agent；包含 LLM 的方案要求 schema 3 能力型 Agent 及模型快照。

本批交付时仅提供内部能力；对外入口与试跑门禁已在第四批接入。`preview` 仅为结构和依赖检查，**不是样本试跑**。暂不支持质检项组合条件、标签项或参数覆盖，不应将现有模型当成最终完整产品契约。

## 第三批：方案任务与独立评分链路

- `SchemeTaskService` 通过现有数据范围校验取得指定发布版本，复用任务创建的会话权限、批量数量及并发限制。发布快照校验 SHA-256 后保存至任务 `ruleSnapshotJson.schemeSnapshot`，不查询当前规则/Agent 草稿，也不允许浏览器提交任意快照。
- `SchemeResultEvaluator` 将规则观察映射为业务质检项：命中可以表示违规或合规；同一会话每质检项只计分一次。检查结果支持 PASS、FAIL、NOT_APPLICABLE、NOT_EVALUATED、REVIEW_REQUIRED、ERROR。空会话不是“不适用”；缺少适用消息的结果不能视为通过。
- 现有会话结果表增加 `finalScore`（两位小数）、`scoreStatus`、`scoringResultJson`、`businessItemResultsJson`，不另建平行结果体系。消息/规则结果只保留检测观察，方案任务的旧整数 score 为 NULL；最终分由会话评分政策产生。
- 批次汇总读取会话最终分，排除待确认、不适用项；没有最终分时返回 NULL。重试其他会话不会隐藏此前已完成会话的分数。历史任务仍按原路径查询，不回填或重新计算。
- 方案 DLS 重试使用完整会话；缺失条件没有正向证据锚点时仍保留真实会话命中。DLS 证据携带规则归属，避免重复投影和跨规则串证据。LLM 当前仍复用单消息检测，**尚未升级为会话级 LLM 契约**。
- 结果页新增业务质检项、评分贡献、待确认/不计分状态及消息定位；不再把方案检测命中直接解释为违规。任务结果和结果分组不将 NULL 转为零分。
- 旧总览的消息平均分排除无分数的方案检测观察，并明确标识为兼容消息评分；**方案专属总览、分政策统计及业务结果导出尚待完成**。旧消息改分入口拒绝方案观察，防止绕开业务评分；业务项目复核尚待接入。

数据库增量 `V1.1.26` 必须先于依赖新列的后端部署；不修改冻结基线，不更新历史行。新任务产生 NULL 消息分后，不能回滚到将 NULL 解释为 0 分的旧前端/统计代码。本批完成内部链路，普通用户入口见第四批。

## 第四批：真实试跑发布门禁与模板使用入口

- 新增 `/api/iqc/schemes` 控制器，维护草稿、检查依赖、创建/恢复试跑、发布、列出已发布模板及按指定发布版本创建任务。页面按维护、发布、使用分权，9 个后端端点各用独立资源码，避免组织服务唯一 code 覆盖 URL/method；不能用普通任务创建接口提交任意方案快照。
- 草稿试跑复用现有任务/会话/结果表和执行队列，最多 20 个会话、并发 1。快照标记 `DRAFT_TRIAL`，包含方案 ID、修订号、内容摘要和完整依赖，不伪装成已发布版本。最近 20 条可见试跑可恢复，避免刷新页面后丢失记录。
- 发布要求：专家明确确认结果；试跑执行成功、无失败消息；与当前草稿修订及完整快照一致；每个会话、每个业务项覆盖完整；无 ERROR/REVIEW_REQUIRED/NOT_EVALUATED，且至少存在适用业务项。样本 FAIL 是业务判断，不代表试跑执行失败，因此不阻止发布。
- 发布时在草稿行锁下再检查内容摘要，避免检查后依赖变化或并发修订。发布记录新增 `sourceTrialTaskId`（`V1.1.27`）；未验证试跑不能调用持久化发布入口。
- 模板任务按用户 + 请求标识派生现有任务主键，以请求内容摘要阻止同一标识替换参数，复用任务表唯一键应对并发插入。重复请求返回原任务；依赖停用检查不替换已发布配置。LLM 方案额外检查其引用的模型、MCP、Skill 当前可用性。
- 前端 `/templates` 以已发布业务模板为主入口，三步完成“确认模板—选会话/名称—执行”；不选择规则或 Agent，不提供分值/策略覆盖。提交后冻结请求参数，创建响应/启动响应丢失均可安全重试。原内置规则素材保留为专家标签页。

## 第五批：任务启动边界的依赖停用检查

- 复用 `SchemeDependencyResolver` 与现有资产校验，不新增服务、表或快照体系。首次排队、失败重试、内部定时入口、暂停恢复均检查方案所引用的明确版本及规则/Agent/模型/MCP/Skill 可用性。
- 执行器取得运行租约后、处理任何会话前再次检查，覆盖“排队时可用，实际启动时已停用”的窗口。拒绝启动时不调用模型、不产生新的检测结果；异步执行沿用失败状态和执行实例错误记录。
- 排队/恢复校验失败时保持原任务状态，不创建新的执行实例或消息任务。不会替换已有规则表达式、提示词、模型参数、评分政策或任务快照。
- 无方案标记的历史任务保留原有语义；明确存在但损坏的方案标记拒绝执行，不能降级为旧评分。
- 边界：这是启动/重试/恢复时的检查，不是运行中逐消息的即时停用开关；检查通过后发生的停用仍存在时间窗口。模板本身的停用生命周期和实时中断属于后续工作。

此批定向回归 4 类 / 53 用例通过（新增启动门禁 6 项、快照保持/兼容 2 项），应用上下文与本地 HTTP 集成检查另行通过；没有修改框架、前端或数据库。部署验收时应在隔离环境执行：

1. 由同一已发布模板创建尚未执行的任务，停用其一条规则，确认启动被拒绝、任务仍为 CREATED、无新执行记录或结果。
2. 重新启用依赖后再启动，确认沿用创建时快照，而非规则的新草稿；运行后暂停，再停用 Agent 或所需模型，确认恢复被拒绝且仍为 PAUSED。
3. 对排队尚未实际运行的任务停用依赖，确认实际启动前失败、执行实例记录停用原因、没有模型调用；此场景需可控制的测试执行队列。
4. 用历史无方案标记任务验证兼容行为；不得在生产批次通过停用共享模型来制造测试条件。

## 接口增量

仍使用 `POST /api/iqc/tasks`，沿用 `iqc:task:create` 权限。示例：

```json
{
  "name": "普通规则批量检查",
  "taskType": "BATCH",
  "conversationIds": ["conversation-id"],
  "ruleIds": ["published-rule-id"],
  "executionMode": "RULE_ONLY",
  "concurrencyLimit": 1
}
```

`executionMode` 可选：RULE_ONLY、INDEPENDENT、AGENT_LLM、RULE_THEN_LLM、LLM_THEN_RULE。省略时保留旧 Agent 模式；新版 Agent 必须由任务显式指定策略。后两种仍是专项兼容路线，不能充当综合模板默认策略。

后端先于新前端发布：旧后端不知道 schema 3 和任务 executionMode。已产生新格式任务后不能直接回退到完全不识别策略快照的旧执行器；如需回滚，应保留兼容后端、停止创建新格式任务，不能只回滚二进制而让存量任务按旧 Agent 模式运行。
