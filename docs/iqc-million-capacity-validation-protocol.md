# 百万会话分片、恢复与容量验收协议

状态：待执行；本文不是压测结果。依据 PRD 第 22、23 章，输入为已处理会话；单租户，沿用组织 owner/group/all。性能数值在实测后基线化，不新增任意 TPS/P95 合格线。

## 复用实现与现有证据

复用 [持久协调设计](adr/20261026-durable-bulk-task-coordination.md)、现有 InspectionTask/TaskExecution、BulkTaskMaterializationService、BulkTaskLifecycleService、DurableInspectionWorker 和实际 MySQL 迁移。不得另建批量队列、简化协调器或使用循环模拟成功替代生产路径。

IsolatedMysqlSelectorShardIT 的 20,137 条/21 页/137 条匹配证明有界扫描与过滤尾页，不是百万规模，更不是百万条执行完成。[跨 JVM 专项](iqc-prd-b-bulk-jvm-restart-validation.md)证明特定认领/回收路径，不能外推完整双 worker 并行。各项必须记录自己的固定源码、测试版本和实际结果。

## 独立验证切片

1. **百万扫描与查询计划**：隔离 MySQL 使用候选迁移，至少 1,000,000 条授权、符合状态且锚点前的已处理会话；另加跨组、锚点开放秒、未来及排除对照。复用实际 scanAllPageAt，分别覆盖全匹配、长段零匹配后尾部匹配和 owner/group/all。按实际数据库排序比较游标，验证无遗漏、无重复、每页最多 1,000 候选、零匹配仍推进、尾页终止及范围不扩大。记录每条真实查询的参数类型、EXPLAIN 和早/中/尾页耗时；特别检查每页 created_time IS NULL 探测与授权 OR 条件，不能只记录带 LIMIT 的主扫描。LIMIT 仅限制返回数，不能证明扫描成本有界。
2. **百万实际物化与恢复**：至少百万条实际选中会话，使用合法已处理消息、原发布版与首次输入冻结，走父任务原子物化和真实持久子任务。仅扫描百万、只选中少量、直接插入子任务或把子状态直接更新成成功，不满足此项。记录分片/会话/消息各自计数；保留单任务 1,000 上限及 16 MiB 输入保护，实际分片数以配置与数据为准。至少在早/中/后检查点分别做提交后进程强杀，重启原 worker 恢复；验证父 EID、唯一父子序号、已提交片完整输入/hash 不变，未提交片原子回滚且可继续，无重复业务输出。
3. **百万完整执行与混合负载**：原 scheduler/worker 实际调度并执行所有选中会话，使用原受支持的可确定 Rule/Regex/Metric 节点，完整结果持久化并汇总父终态。同时运行普通任务，验证其可取得执行机会；覆盖父暂停/恢复/取消、满槽停止传播与两个实际 worker 进程竞争。受控失败须沿原重试/恢复路径；仅认领竞争或人工调用 discover 一次不代表此项完成。可将多个故障场景作为独立运行，避免一次取消使完整运行的分母失真。
4. **模型、组织与外部边界**：受控 actor、确定性节点的结果分别标注，不能推为远程 PDP、供应商配额/GPU/Token 成本或外部动作履约。真实组织授权、撤权和模型/外部容量仍各按独立验收执行；本协议不启用默认关闭的 MQ、v2 或外部副作用。

## 记录与判定

每次记录运行 ID、源码/测试完整 SHA、迁移及 checksum、数据库/Java 版本、CPU/内存/存储、索引和执行计划、数据生成参数/随机种子/规模与消息大小分布、并发与配额、预热/测量窗口。数据应确定可复现，不含生产个人信息。

记录导入耗时（与处理耗时分开）、扫描/物化/排队/执行/恢复耗时、吞吐、各阶段延迟分布及 P95、进程 RSS/堆峰值、数据库 CPU/IO/锁等待和错误/重试/积压；注明采样方式和缺失测量。冻结检查点、前后计数/hash、实际进程 PID 与退出状态、日志和报告路径应可追溯。已有 Micrometer 指标应优先复用，不新建第二套业务计量。

第一项通过只关闭百万扫描证据缺口；第二项通过才能支持百万实际分片/检查点恢复；第三项是完整执行和混合负载证据。单独的绿色 CI、20k 外推、几条代表性子任务、全部状态手工终态、缺测填零或仅耗时日志均不能宣布百万验收完成。性能基线不得据单次最优值或不同机器结果相加；报告失败与环境限制，后续据实确定 SLO。
