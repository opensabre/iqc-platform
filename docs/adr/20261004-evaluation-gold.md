# I3 金标与候选样本复用

状态：实施中，尚未接入发布门禁。

## 现有能力与缺口

`QualityOperationsService.createSample` 与 `iqc_quality_sample` 已提供结果来源、消息内容快照、期望 JSON、标签和数据权限。继续作为候选池使用，不新增候选样本表。

当前内容快照仅为一条消息；`ENABLED` 不表示人工审核；没有完整会话、业务上下文、金标协议、标注/审核身份或不可变版本。不能据此运行可复现的 Pipeline 回归，也不能把已有自由 JSON 自动提升为金标。

## 决定

先增加独立、强类型的金标契约。Finding 期望复用现有类型和状态，保留未知/冲突等状态；金标不伪造引擎 Source。证据引用必须在冻结消息中存在。完整会话和业务上下文冻结，标注人与审核人必须不同，保存来源和难度。

后续数据集版本引用经审核的样本快照；数据集 BASIC/BOUNDARY/RISK/ADVERSARIAL/REGRESSION/CUSTOM 分类与候选 POSITIVE/NEGATIVE/FALSE_POSITIVE/FALSE_NEGATIVE 分类分别保留。新增数据集版本持久化前记录具体模型与复用任务执行的边界。

评分状态/分数、风险和标签期望可选保存；标签结构化值与版本关联、各层完整指标、对照实验、门禁与强制发布审计仍需实现。首个金标契约不是完整评测功能，既有候选创建/列表 API 保持兼容。

## 持久化与协作边界

V1.1.38 在已有 `iqc_quality_sample` 上追加金标草稿/修订/状态/最新审核版本；新增 `iqc_quality_sample_version` 仅保存每个精确修订的不可变审核决定及快照/hash，不创建平行样本主库。审核身份来自登录上下文，禁止标注人自审；退回必须生成新修订再审核。V1.1.37 留给 B 的候选快照扩容。

V1.1.39 新增 Dataset 与 DatasetVersion，职责是命名样本集合及冻结精确已批准成员版本。已有任务没有此语义；不新建执行任务主表。冻结版本保存成员金标全快照及 hash，后续评测读取版本快照而非实时会话。旧金标批准版本可显式纳入，新草稿不覆盖旧版本；停用样本不能进入新数据集版本。
